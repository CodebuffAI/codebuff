# LESSONS

## Gotchas discovered during the audit

- **The `sc-*` / `flow-nexus-*` skill family is NOT on disk in this fork.** `grep -r 'source-command|flow-nexus|sc-git|sc-workflow|sc-task|sc-implement|sc-test|sc-analyze'` across `*.ts/*.tsx/*.md/*.json` returns 0 hits. The 30-odd `sc-*` / `flow-nexus-*` skill ids visible in the harness's pre-loaded skill catalog are **runtime-injected by the agent harness driving this conversation**, not files in the fork. They are NOT a fork-cleanable surface. Documenting this so future audits do not re-investigate.
- **The CLI's bundled-agents artifact does not bake in skill ids.** `cli/src/agents/bundled-agents.generated.ts` has 15 hits for `"skill"` but every one is the *tool name* listed in agent `toolNames` arrays — not skill ids. So even the published CLI does not carry `sc-*` / `flow-nexus-*` ids as data. Confirms the harness-injection conclusion.
- **On-disk skill surface is tiny.** `glob **/SKILL.md` returns 4 paths: 3 real skills (`.agents/skills/{meta,cleanup,review}/SKILL.md`) + 1 user scaffold (`common/src/templates/initial-agents-dir/skills/example-skill/SKILL.md`). The "legacy skill prune" scope collapses to: 2 stale slash-command description strings + 2 vestigial on-disk skills.
- **`gpt-5.4` appears elsewhere in the repo as a legitimate BYOK model id** — `common/src/constants/chatgpt-oauth.ts`, `sdk/src/provider-config.ts`, `common/src/templates/initial-agents-dir/types/agent-definition.ts`, README, `docs/local-mode.md`, `docs/configuration.md`, `docs/openbuff-provider-model-setup-ux.md`, plus `evals/buffbench/judge.ts` and `evals/buffbench/__tests__/proposals.test.ts`. These are NOT legacy-skill markers and are OUT OF SCOPE. The only `gpt-5.4` strings in scope are the two human-facing description strings in `cli/src/data/slash-commands.ts:96,125`.
- **`cleanup` and `review` skills are fully duplicated by the fork's root prompts.**
  - `cleanup` is duplicated by the "Code Craftsmanship / Simplicity & Minimalism / Code Reuse" section of the root orchestration prompt, inherited by every spawned agent. Both the cleanup skill and the root section say "simplify, reuse functions, lower complexity."
  - `review` is duplicated by (a) the `/review` slash command handler (`cli/src/commands/command-registry.ts:940` `review` handler → `buildReviewPromptFromArgs` in `cli/src/commands/prompt-builders.ts:155`) AND (b) the auto-spawned `code-reviewer` reviewer-gate that runs after every edit (wired from `agents/base2/base2.ts` validation/reviewer gate lifecycle).
  - Keeping them means every agent sees the same procedural content twice — once via the discoverable `<available_skills>` XML, once via the inherited root prompt. Delete is the right call.
- **`meta` skill is NOT duplicated** — its 5 bullets cover `bun --cwd` monorepo invocation, SDK-eval artifact persistence, structured-log debugging, scoped-diff validation, and validation-first ordering. None of these are in the root prompt or any agent template's `systemPrompt`/`instructionsPrompt`. Genuinely valuable, correctly scoped as a skill. Keep.
- **The skill loader's discovery path is unchanged by this prune.** `sdk/src/skills/load-skills.ts getDefaultSkillsDirs()` scans `~/.agents/skills`, `~/.agents/skills`, `{cwd}/.claude/skills`, `{cwd}/.agents/skills`. After deleting `cleanup/SKILL.md` + `review/SKILL.md`, `discoverSkillsFromDirectory()` simply finds fewer files; `formatAvailableSkillsXml()` in `common/src/util/skills.ts` serializes two fewer `<skill>` entries. No code change in the loader is required.
- **Snapshot test risk is low but non-zero.** If any test in `cli/src/commands/__tests__/` or `sdk/src/__tests__/load-skills.test.ts` hard-codes the available-skills XML or the slash-command description strings, deleting the skills / editing the descriptions will fail that test. M1's validation gate runs the full CLI test suite and will surface this. Fix-forward by re-recording the snapshot.
- **Session-independence is preserved.** This session shares only the freebuff-grep gate with `upstream-byok-beneficial-changes`. No file it touches (`.agents/skills/*`, `cli/src/data/slash-commands.ts`) is also touched by any M1-M6 milestone of the upstream-port session, so the two sessions can be executed in either order without conflict.

## M1 execution gotchas — 2026-07-06 — 2026-07-05T21:11:08.727Z

- **`bun --cwd <pkg> run <script>` flag-order gotcha is real.** `bun --cwd cli run typecheck` prints Bun's general help menu and exits 0 WITHOUT running anything — it interprets the args as a positional command path. The correct invocation is either `cd cli && bun run typecheck` or `bun run --cwd cli typecheck` (flag before the script name). This is exactly the `bun run --cwd` warning recorded in `.agents/skills/meta/SKILL.md` — which survived the prune and is the right reference. Future milestones in this repo should use `cd <pkg> && bun run <script>`.
- **`git rm` auto-prunes empty parent directories.** `git rm .agents/skills/cleanup/SKILL.md .agents/skills/review/SKILL.md` removed both files AND the now-empty `.agents/skills/{cleanup,review}/` directories. A follow-up `rmdir` was redundant and reported `No such file or directory` — that is expected and not a failure.
- **`find . -name SKILL.md` surfaces the test-repo fixture copy under `evals/test-repos/openbuff-HEAD/.agents/skills/{cleanup,review,meta}/SKILL.md`.** These are a separate test-repo fixture (an older snapshot of the repo used by buffbench evals), explicitly out of scope per SPEC. When verifying the `glob **/SKILL.md == 2` acceptance criterion, scope the find to `./.agents/skills/` + `./common/src/templates/` or filter out `./evals/test-repos/` to avoid false positives.
- **No snapshot-test regression from the description edits.** `cli/src/commands/__tests__/command-args.test.ts` + `cli/src/commands/__tests__/command-suggestions.test.ts` both pass unchanged — they assert command names + aliases + arg-parsing, not the description strings or the `formatAvailableSkillsXml` output. The `formatAvailableSkillsXml` change (two fewer `<skill>` entries) had no snapshot test to regress against.
- **Q1/Q2 defaults accepted without user override.** Both replacement descriptions used the defaults from PLAN.md (`Create a durable plan with the configured planner` / `Review code changes with the configured reviewer`). User did not exercise the alt options; the defaults are reversible text edits if the user wants different copy later.

Decisions reaffirmed during execution:
- The fold-into-`base2.ts` contingency was NOT exercised — `meta` remains correctly scoped as a skill. `base2.ts` is unchanged.
- The `cleanup` and `review` skills are gone from disk; users who want custom cleanup/review procedural content should create a differently-named skill (e.g. `.agents/skills/my-cleanup/SKILL.md`) per the SPEC risk note.

Follow-up notes:
