# LESSONS

## Gotchas discovered during this audit

- **Upstream squashes all history into "Sync public snapshot from freebuff-private" commits.** `git log upstream/main..HEAD` / `HEAD..upstream/main` are useless for understanding what changed — only `git diff HEAD...upstream/main -- <path>` (tree diff) surfaces real changes. Future audits must be diff-driven, not log-driven.
- **The 1461-file / +20k / -332k diffstat is misleading.** Most of the deletions are (a) `agents/__tests__/data/run-state-context-overflow{,2}.json` (~64k lines of test fixtures removed upstream), (b) the entire `web/` product subtree (-), and (c) `.github/workflows/*` churn. These are noise. Real port surface is ~30–40 files across `common/src/{constants,tools}`, `packages/agent-runtime/src`, `cli/src/{utils,commands,components}`, and `agents/{base2,types}`.
- **Many upstream CLI components couple transitively to `IS_FREEBUFF` / `freebuff-session` / hosted auth.** Every CLI port (M4/M5) needs an import audit — do not assume a file is portable just because it's in `cli/src/components/`. Example: `freebuff-model-selector.tsx`, `status-bar.tsx`, `session-ended-banner.tsx` all import hosted-session state.
- **`base2.ts` upstream imports from `freebuff-models.ts` and `free-agents.ts`** (`FREEBUFF_KIMI_MODEL_ID`, `FREEBUFF_MINIMAX_*`, `FREEBUFF_REVIEWER_AGENT_ID_BY_MODEL`, `canFreebuffModelSpawnGeminiThinker`). Porting the base2 changes (#3) without also pulling the freebuff constants would break compilation. M3 must either stub these or restrict base2 changes to the slices that don't transitively require freebuff model IDs (default model bump, `noReview`, system-prompt improvements, `read_url`/`gravity_index`/`render_ui` tool enablement, Composio gate).
- **The OpenRouter GPT-5 default in `model-config.ts` was rolled back** (`gpt-5.5 → gpt-5.1`) upstream. The fork is on `5.5`. This is intentional upstream regression for their hosted load; BYOK users pick their own model, so SKIP this hunk.
- **Upstream introduced `supportsAssistantPrefill(model)` + a runtime guard in `run-agent-step.ts`.** This is not a cosmetic change — Claude 4.6+ ("opus-4.8" and Fable) returns `"This model does not support assistant message prefill"` for any request whose final message is an assistant message (e.g. a continuation after a think-only response). Without this guard, BYOK Anthropic users on Claude 4.6+ hit a 400 on continuation steps. Highest-value port.
- **`toTokenCountInputSchema()` is paired with the prefill fix and also fixes a separate bug:** Zod schemas passed to Anthropic `count_tokens` as `inputSchema` were shipping Zod internals (`def`/`shape`) instead of JSON Schema, and union/intersection schemas arrived without `type`, triggering `tools.N.custom.input_schema.type: Field required`. Both fixes ride together; do not split them.
- **Upstream swapped `linkup-api.ts → serper-api.ts`** for `web_search`, renaming the file and changing the response shape (richer SERP fields). This is a hard fork decision: BYOK users may not have a Serper key. Recommended resolution: env-gate (`SERPER_API_KEY` present), with Linkup kept as a fallback — but this is more work than a cherry-pick. Surface to the user as Q1.
- **`ENABLE_COMPOSIO_TOOLS = false` is upstream's own gate** on the new Composio tool family. Porting the scaffolding with the gate intact is safe for offline/BYOK default; enabling is opt-in. This is the template for any future opt-in third-party integration.
- **`freebuff-models.ts` (~500 lines) is the single most host-coupled constants file** — deployment hours, premium/limited session limits, streak rewards, GLM referral cap, waiting-room model list. SKIP in full; but `model-config.ts` upstream's new `mimoModels`/`minimaxModels`/`moonshotModels` are pulled *out* of freebuff-models into shared model-config, which makes them safely portable. The split was deliberate on upstream's part.
- **No-code-change decisions catalogued as SKIP:** freebuff referrals/streaks/engagement/ads/landing/waiting-room, `reddit-capi`, `engagement-tracker`, `freebuff-privacy`, BigQuery/log-schema growth, `.github/workflows/*`, `web/`, `freebuff/`, `agents/base2/base2-free-*.ts` and `agents/reviewer/code-reviewer-{glm,mimo,minimax}-*.ts` freebuff-specific agent variants, OpenRouter GPT-5 downgrade.

## Decisions made during audit

- Default disposition: **SKIP** for anything pulling `freebuff-*`, `IS_FREEBUFF`, hosted auth, telemetry, BigQuery, `web/`, `.github/`, or release-bundle auth rewires. **PORT** for runtime correctness (prefill token-count, network-error UX), purely-local CLI utilities (terminal watchdog, atomic chat writes, chat-meta sidecar, `/copy`, chat-input key intercept), the `read_url` tool, model-config registry refresh (minus `'free'` prefix), `gravity_index` contract refresh, and the base2 system-prompt + tool-list refresh. **ADAPT** for Composio (gated `false`) and `cli-args.ts` (prune `IS_FREEBUFF` branch).
- Milestone ordering M1 → M6 prioritizes runtime correctness first, then the self-contained `read_url` tool, then the base2/model-config refresh (which has the trickiest freebuff import coupling), then CLI utilities, then CLI UI + arg parser, then the gravity/web-search contract refresh (which needs the user's Q1 decision).

## Follow-up notes

- After M1 lands, re-check `packages/agent-runtime` tests; upstream added `run-agent-step-preflight.test.ts` and `to-token-count-input-schema.test.ts` that should mostly port directly.
- After M3, validate that `agents/__tests__/base2.test.ts` (+160 lines upstream) passes with the adapted base2 — it's the regression net for the base2 tool-list + spawnable-agents changes.
- After M4, run a `kill -9` on a dev CLI session to confirm the terminal watchdog restores the terminal — that's the acceptance test for #10.
- Periodically (every few weeks), re-run `git fetch upstream && git diff --stat HEAD...upstream/main` to detect new upstream changes; reuse this plan's verdict-table structure rather than re-deriving categories.
