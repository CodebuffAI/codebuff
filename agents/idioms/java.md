# Java Idioms

- Preserve package structure, build-tool conventions, visibility modifiers, and existing annotation/framework patterns.
- Prefer clear types, small methods, immutable values where practical, and explicit exception boundaries.
- Use collections, streams, records, and optionals only where they improve readability in the local style.
- Keep dependency injection, logging, and transaction boundaries aligned with the surrounding code.
- Follow existing test style, formatter output, and static-analysis expectations before adding new abstractions.
