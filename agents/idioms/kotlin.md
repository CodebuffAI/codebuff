# Kotlin Idioms

- Prefer null-safety, data classes, sealed types, extension functions, and immutable values when they fit.
- Preserve Gradle, Android/Ktor/Spring, coroutine, formatter, and package conventions already in the repo.
- Use scope functions sparingly and only when they make ownership and side effects clearer.
- Keep suspend functions, flows, and dispatcher/threading boundaries explicit in async code.
- Avoid Java-style boilerplate when Kotlin language features express the contract more clearly.
