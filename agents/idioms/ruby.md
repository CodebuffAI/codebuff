# Ruby Idioms

- Keep code expressive and small; prefer clear objects, blocks, and enumerable helpers over over-engineering.
- Preserve Rails, RSpec, Bundler, RuboCop, or project-local conventions already present in the repo.
- Use keyword arguments, safe navigation, and guard clauses where they improve readability.
- Keep metaprogramming narrow and well-contained; avoid surprising monkey patches.
- Respect transaction, validation, callback, and dependency boundaries in framework code.
