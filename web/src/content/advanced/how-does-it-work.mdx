# How does Openbuff actually work?

Openbuff runs multiple agents, each tuned for a specific task.

## The Orchestrator

The main agent ("Buffy") runs on Claude Opus 4.7. It reads your prompt, gathers context, and spawns subagents. The orchestrator is available in several variants:

- [`base2`](/publishers/openbuff/agents/base2) - Default mode orchestrator
- [`base2-lite`](/publishers/openbuff/agents/base2-lite) - Lite mode (faster, cheaper)
- [`base2-max`](/publishers/openbuff/agents/base2-max) - Max mode (best-of-N selection)
- [`base2-plan`](/publishers/openbuff/agents/base2-plan) - Plan mode (no file writes)

## Subagents

- [**File Picker**](/publishers/openbuff/agents/file-picker) (Gemini 2.0 Flash) - finds relevant files
- [**Code Searcher**](/publishers/openbuff/agents/code-searcher) - grep-style pattern matching
- [**Researcher**](/publishers/openbuff/agents/researcher) (Gemini 3.1 Flash Lite) - web and docs lookup
- [**Thinker**](/publishers/openbuff/agents/thinker) (Claude Opus 4.7, GPT-5.4) - works through hard problems
- [**Editor**](/publishers/openbuff/agents/editor) (Claude Opus 4.7, GPT-5.1, Kimi K2.6) - writes and modifies code
- [**Reviewer**](/publishers/openbuff/agents/reviewer) (Claude Opus 4.7, Kimi K2.6 in Lite mode) - catches bugs and style issues
- [**Basher**](/publishers/openbuff/agents/basher) (Gemini 3.1 Flash Lite) - runs terminal commands

## Best-of-N Selection (Max Mode)

In Max mode, Openbuff spawns multiple editors with different strategies. A selector compares the outputs and picks the best one.

## The Pipeline

1. Tree-sitter scans your repo and builds a code map
2. File pickers and searchers find relevant code
3. Thinkers analyze the problem if needed
4. Editors generate changes
5. Reviewers check for issues; bashers run tests

All LLM inference runs directly against your configured providers via `openbuff.json`. Your code stays local; only relevant context is sent to your configured model providers.
