# Working with Large Projects

Openbuff works on large repos (we test against VS Code). Openbuff is an independent, local-first BYOK fork of Codebuff, so large-project usage depends on your configured providers rather than hosted credits. If it wanders or sends too much context to your provider, try these.

## Directory-Based Approach

Start Openbuff in the part of the repo you care about:

```bash
    cd backend
    openbuff
```

Or set `--cwd`:

```bash
    openbuff --cwd backend
```

This keeps the context tight.

## Knowledge Organization

For big trees, keep knowledge close to the code:

- Add `knowledge.md` files in important subdirectories:

  ```
  services/
  auth-service/
      knowledge.md
      src/
  user-service/
      knowledge.md
      src/
  api-gateway/
      knowledge.md
      src/
  ```

- Keep each file focused on that area
- Link related files when the areas overlap
- Use the root `knowledge.md` for cross-cutting notes

## Effective Communication

When asking for work in a large repo:

- Point to exact paths
- Mention related files up front
- Break large changes into smaller requests
- Use `--max` when you need Openbuff to load more files

## Performance Tips

- Trim noise with `.codebuffignore` and `.gitignore`
- Start in the most relevant subdirectory
- Split broad refactors into stages
- Let Openbuff handle file discovery instead of pasting long file lists
