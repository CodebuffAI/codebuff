# Troubleshooting

[Open an issue](https://github.com/AnzoBenjamin/openbuff/issues) or check existing reports.

## Install Node

If you don't have `npm`, [get Node here](https://nodejs.org/en/download).

## Delete local cache

Openbuff stores files at `~/.config/manicode` including the binary `openbuff`. Sometimes deleting the binary and restarting openbuff will fix issues.

## Version

The latest version of the Openbuff client can be found on the [npm page](https://www.npmjs.com/package/openbuff).

Run `openbuff --version` to make sure you're on the latest version.

Openbuff should auto-update. If not, try the steps below.

## Install failed

If `npm install -g openbuff` gave you an error regarding permissions, try using setting the owner of that directory to your user.

Mac/Linux: `sudo chown -R $(whoami) <directory>`

Windows: `cmd takeown /F <directory> /R /D Y`

Otherwise reinstall node with [nvm or fnm](https://nodejs.org/en/download) and rerun the install.

## Accessing Your Chat History

Your conversation history with Openbuff is stored locally (and nowhere else) at `~/.config/manicode/projects/<your-project-name>/chats`.

Include recent chats if you ask for help.

#### Conflicting Node/npm Installations (Homebrew vs. nvm)

One common cause is having conflicting Node/npm installations on your system, particularly between Homebrew and nvm. Here's how to diagnose and fix this:

1. Check your Node and npm paths:

   ```bash
   which node
   which npm
   ```

   If these point to Homebrew paths (e.g., `/opt/homebrew/bin/`) instead of nvm paths (e.g., `~/.nvm/versions/`), that's the issue.

2. Check what packages depend on Node through Homebrew:

   ```bash
   brew uninstall node
   ```

   This will show you any packages that depend on Node.

3. If you don't need those packages anymore, you can uninstall them. This will automatically remove Node as a dependency.

4. After this cleanup, your `which node` and `which npm` commands should point to your nvm installation, and Openbuff should work as expected.

### Command Not Found

If you see "command not found" when trying to run Openbuff:

1. Ensure Openbuff is installed globally: `npm install -g openbuff`
2. Check that your PATH includes npm's global bin directory
3. Try running `which openbuff` to verify the installation location

### Directory Not Empty

If you see an error like this:

```bash
npm ERR! code ENOTEMPTY
npm ERR! syscall rename
npm ERR! path /some/path/to/node_modules/openbuff
npm ERR! dest /some/path/to/node_modules/.openbuff-SOMEHASH
npm ERR! errno -66
npm ERR! ENOTEMPTY: directory not empty, rename '/some/path/to/node_modules/openbuff' -> '/some/path/to/node_modules/.openbuff-SOMEHASH'
```

It means you have a directory named `.openbuff-SOMEHASH` in your node_modules directory. This is a temporary directory created by npm when installing packages. You can safely delete this directory and try again:

```bash
rm -rf /some/path/to/node_modules/.openbuff-SOMEHASH
```

### Automating Openbuff with tmux

If you're trying to automate Openbuff using tmux (e.g., for scripting or testing), standard `tmux send-keys` won't work correctly. Characters will be dropped or garbled.

**The Problem:**

```bash
# ❌ Doesn't work - characters get dropped
tmux send-keys -t openbuff "hello world"
tmux send-keys -t openbuff Enter
# Result: Only "d" appears in the input!
```

**The Solution:**

Use bracketed paste mode by wrapping your input in escape sequences:

```bash
# ✅ Works correctly
tmux send-keys -t openbuff $'\e[200~hello world\e[201~'
tmux send-keys -t openbuff Enter
# Result: "hello world" appears correctly!
```

This tells the terminal that the input is a paste operation, which Openbuff handles atomically.

**Helper script:**

```bash
send_to_openbuff() {
  local session="$1"
  local text="$2"
  tmux send-keys -t "$session" $'\e[200~'"$text"$'\e[201~'
}

# Usage:
send_to_openbuff my-session "fix the bug in main.ts"
tmux send-keys -t my-session Enter
```
