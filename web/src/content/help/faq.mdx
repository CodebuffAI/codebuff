# FAQ

## What can Openbuff be used for?

Software development: Writing features, tests, and scripts across common languages and frameworks. It can also run CLI commands, adjust build configs, review code, and answer questions about your repo.

## What model does Openbuff use?

Openbuff uses the provider/model routes you configure in `openbuff.json`. Default, Max, Plan, and individual subagents can all be mapped to different models, but Openbuff itself does not provide hosted inference or a fixed model lineup. See [What models do you use?](/docs/advanced/what-models) for the full breakdown.

## Is Openbuff open source?

Yes. It's Apache 2.0 at [github.com/AnzoBenjamin/openbuff](https://github.com/AnzoBenjamin/openbuff).

## Do you store my data?

Openbuff does not have a backend — your code is sent only to the model providers you configure in `openbuff.json`. Openbuff itself never receives your codebase or chat data.

## Do you use model providers that train on my codebase or chat data?

No. You configure your own providers via `openbuff.json`. Check the data policies of your chosen providers directly.

## Can I trust Openbuff with full access to my terminal?

If you want isolation, use the [Dockerfile](https://github.com/AnzoBenjamin/openbuff/tree/main/utils/docker) to run Openbuff against a scoped copy of your codebase.

## Can I specify custom instructions for Openbuff?

Yes. Add `knowledge.md` files to describe patterns, constraints, and commands. Openbuff also reads `AGENTS.md` and `CLAUDE.md` if present. Per directory, it picks one: `knowledge.md` first, then `AGENTS.md`, then `CLAUDE.md`. Openbuff updates existing knowledge files but won't create them unless you ask.

You can also create a **home directory knowledge file** (`~/.knowledge.md`, `~/.AGENTS.md`, or `~/.CLAUDE.md`) for preferences that apply across all projects. File name matching is case-insensitive. See [Knowledge Files](/docs/tips/knowledge-files#home-directory-knowledge-files) for details.

## Can I tell Openbuff to ignore certain files?

Openbuff by default will not read files that are specified in your `.gitignore`. You can also create a `.codebuffignore` file (legacy compatibility name) to specify additional files or folders to ignore.

### What if I want Openbuff to not ignore some files in the `.gitignore`?

The `.codebuffignore` file follows standard `.gitignore` negation rules as well! So to ignore a file from git but not from Openbuff:

```.gitignore
path/to/file
```

```.codebuffignore
!path/to/file
```

Take note that if you want to negate something in a nested subdirectory, you need to first negate each of the parent directories first (assuming they were ignored by some other rule). So something like:

```.gitignore
# ignore everything
**
```

```.codebuffignore
# negate: path/to/file
!path/to/
!path/to/file
```

The final set of files ignored by Openbuff are determined by the contents of `.gitignore`, followed by the contents of `.codebuffignore`.

## How does Openbuff work?

Openbuff runs specialized local agent loops: one can find files, another can reason through the problem, another writes code, and another reviews. All model calls go to your configured providers. In Max mode, multiple implementation proposals compete before validation and review gates run.

## How does Openbuff compare to Claude Code?

See [Openbuff vs Claude Code](/docs/advanced/claude-code-comparison) for a detailed comparison. Short version: Openbuff is faster, cheaper, and handles large codebases better.
